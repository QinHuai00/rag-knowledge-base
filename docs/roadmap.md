# 优化路线（初版 V1 → 进阶 V7）

本文件是 README 的配套路线图。初版刻意只做"能跑通、能评测、能复现"的最小完整链路，
下面每一级优化都遵循 **一次只改一个变量 + 用同一份评测集对比** 的原则。

| 级别 | 优化主题 | 改哪里 | 度量指标 | 预期收益 |
| --- | --- | --- | --- | --- |
| V1 | 当前初版：固定切分 + 纯向量召回 | 全链路 | Recall@K / 拒答正确率 / 耗时 | 基线 |
| V2 | 切分升级：段落/标题感知 → 父子块 | `app/splitter.py` 新增两级切分、`app/parents.py` 存父块、`app/ingest.py`、`app/generator.py` | Recall@K、答案要点覆盖率 | 答案更完整，召回不降 |
| V3 | 召回升级：BM25 + jieba 分词 + RRF 融合 | 新增 `app/bm25.py`，改 `app/retriever.py` | Recall@K（重点看编号/专有名词题） | 字面匹配补向量短板 |
| V4 | 精排升级：交叉编码器 Rerank | 新增 `app/reranker.py`，改 `app/retriever.py` | Top-5 命中率、延迟 | 候选质量再提一档 |
| V5 | 查询侧：查询改写 / 多查询 | 新增 `app/query_rewrite.py` | Recall@K、误召率 | 口语化提问更稳 |
| V6 | 生成侧：引用校验、阈值校准、上下文压缩 | 新增 `app/citation.py`、`app/context.py`，改 `app/generator.py` | 引用合法率、拒答正确率 | 少编、少答非所问 |
| V7 | 工程化：增量入库、缓存、并发、SSE、观测、Docker | `app/ingest.py`、`app/server.py`、新增部署文件 | TTFT、QPS、缓存命中率 | 可演示、可部署 |

## 怎么验证每一级真的有效

```bash
# 同一份评测集，改前 / 改后各跑一次
python -m app.cli eval
# 阈值变化时，重新校准（离线点积与在线余弦分数不可比）
python -m eval.calibrate

# 一次只改一个变量；结果记在同一张表里：
# | 版本 | 改动 | Recall@5 | 拒答正确率 | 平均耗时 |
# | V1  | 基线 |   __%    |    __%     |  __ms    |
# | V2  | 父子块 | __%    |    __%     |  __ms    |
```

> 诚实约定：离线哈希向量 + 抽取式回答只能证明**工程链路正确**，不能当作真实语义检索效果。
> 接真实 BGE / 大模型后必须用同一份评测集重测，简历只写那次测出来的数字。
